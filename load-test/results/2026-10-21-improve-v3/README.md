## 작업 4 — 서버 쪽 읽음 모으기 (`34af63f` 코드, `fe52bd7` 측정 설정)

`chat.read.aggregate.enabled`(기본 끔)로 켠다. 측정에서는 `READ_AGGREGATE=true`로 켠다. 처리 위상은 서버 순번으로 정한다(app1 0ms, app2 250ms, 지표 `chat_read_agg_phase`로 확인).

- 테스트: 서버 216/216(`ReadAggregatorTest` 포함: 두 서버가 겹치는 행을 동시에 처리해도 교착 없이 최대값, 중복 처리 수 지표), 프런트 `readThrottle` 18/18·lint·build, load-test 9/9
- 브라우저와 생성기는 같은 규칙 파일(`readThrottle.js`)을 쓴다. 모으기 실행의 생성기 설정은 `readRetryMode: backoff`, `readConfirmMs: 2000`(스냅샷 확인 재전송)이다

- 모으기를 켜면 읽음 보고는 권한 캐시 확인과 메모리 기록만 하고 202로 끝난다(DB에 가지 않는다). 그래서 Prometheus가 긁는 순간(5초마다)에 처리 중인 보고가 잡히지 않았다. L은 0(지표 해상도 이하)이다
- **K = max(32, 10 × L) = 32.** 5-1·5-2는 K=32로 잰다(벌크헤드는 지우지 않고 안전망으로 둔다)

  - 교착 0, 실패 0, 늦은 주기(t > 500ms) 0, 범위 밖·멤버 아님 0, 두 서버 중복 처리(stale) 0
