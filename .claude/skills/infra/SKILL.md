# 인프라 (DevOps)

이 세션의 주제는 CI/CD, 배포 환경, 클라우드, 컨테이너, K8s, 오토스케일링이다. 인프라의 결정은 사용자가 한다. 사용자는 구체적인 설정 방법과 설치에 익숙하지 않으므로, 이 세션은 그 과정을 안내하고 돕는다.

공통 규칙과 코드 작업 규칙은 CLAUDE.md를 따른다. 아래는 이 세션에만 해당하는 내용이다.

## 다루는 것

- CI/CD
- 배포 환경, 클라우드
- 컨테이너, K8s 등 오케스트레이션
- 오토스케일링
- 모니터링 도구를 서버에 띄우고 연결하기
- 부하 테스트용 임시 테스트 환경의 구축과 삭제

## 일하는 방식

- 결정은 사용자가 한다. 선택지가 있으면 대안과 트레이드오프(특히 비용)를 제시하고, 사용자가 고르게 한다.
- 누가 어떤 작업을 할지는 사용자가 작업마다 정한다.
  - **사용자가 직접 하는 작업:** 단계별로 안내한다. 각 단계에서 무엇을 왜 하는지 설명한다. 사용자가 직접 해보며 익히는 것이 목적이다.
  - **AI가 맡는 작업:** 핵심에서 멀고 부수적인 설정이나 코드 작업이다.
  - 지정이 없거나 어느 쪽인지 애매하면 묻는다.
- 실제 환경(클라우드, 서버)에 대한 명령은 기본적으로 AI가 실행하지 않는다. 명령어와 방법을 알려주고, 사용자가 직접 실행한다. 사용자가 명시적으로 맡긴 경우에만 AI가 실행하며, 이때도 아래 dry-run 규칙을 따른다.
- 사용자는 AWS를 웹 콘솔로 다뤄왔고 AWS CLI는 써본 적이 없다. 클라우드 작업은 기본적으로 콘솔 기준으로 안내한다. CLI가 더 적합하면 이유를 설명하고 사용자가 고르게 한다.

## 자동 배포

main에 머지되면 자동으로 운영에 배포된다. 그래서 배포 파이프라인은 다음을 갖춘다.

- main 브랜치 보호: PR 없이 푸시할 수 없고, CI(빌드와 테스트)를 통과해야 머지할 수 있다.
- 배포 후 헬스 체크로 정상 동작을 확인한다.
- 문제가 생기면 이전 버전으로 되돌릴 수단을 미리 준비한다.

## 되돌리기 어려운 작업: dry-run 먼저

실제 환경(클라우드, 서버, 운영 데이터)에 영향을 주는 작업은 실행 전에 다음을 지킨다.

1. 실행하면 무엇이 바뀌는지 미리 보여준다 (dry-run, plan, diff 등).
2. 사용자의 승인을 받는다.
3. 승인 후에만 실행한다.

특히 삭제, 덮어쓰기, 운영 환경 변경, 외부에 포트나 서비스를 여는 작업은 반드시 이 순서를 따른다.

## 비용

- 실제 지출이 예상되는 지점이 나오면 진행 전에 바로 보고한다.
- 보고에는 무엇에 비용이 드는지, 예상 금액, 무료 대안이 있는지를 포함한다.
- 무료 티어나 무료 서비스를 쓰는 경우, 한도를 넘으면 과금되는 지점을 함께 알려준다.

## 부하 테스트 환경

- 부하 테스트는 운영 서버가 아니라 테스트할 때만 띄우는 별도 환경에서 한다.
- 관측 세션에서 요청이 오면 운영과 최대한 같은 구성으로 테스트 환경을 띄우고, 테스트가 끝나면 삭제한다.
- 띄우기 전에 예상 비용(띄워둘 시간 기준)을 보고한다. 삭제를 잊으면 비용이 계속 나가므로, 테스트가 끝나면 삭제 여부를 확인한다.

## 비밀 정보

- 비밀 키, 비밀번호, 토큰, 접속 정보는 레포에 절대 쓰지 않는다. 이 레포는 공개 레포다.
- 설정 파일에는 실제 값 대신 자리표시자(placeholder)를 쓴다.
- 실제 값의 입력과 설정은 사용자가 직접 한다. 어디에 무엇을 넣어야 하는지 안내한다.

## 배포 환경

배포 환경은 아직 정해지지 않았다. 사용자가 써본 조합은 AWS, Cloudflare, Tailscale, 홈 서버, 무료 서버 서비스다. 환경을 정하는 논의가 시작되면 이 경험을 출발점으로 비용과 트레이드오프를 비교해 제시한다.

## 장애와 배포 실패 보고

배포 실패나 장애가 나면, 이 세션 안에서 다음을 정리해 보고한다. 사용자가 나중에 records에 옮겨 정리할 때 쓴다.

- 상황: 무엇을 하다가 발생했는가
- 원인: 확인된 원인, 또는 추정 원인과 그 근거
- 원본: 로그, 에러 메시지를 요약하지 말고 그대로

## 멈출 조건 (인프라)

공통 멈출 조건에 더해, 다음 상황에서도 멈추고 사용자에게 보고한다.

1. 실제 지출이 예상될 때
2. 실제 환경에 영향을 주는 작업을 실행하기 전 (dry-run 결과와 함께)
3. 비밀 정보를 다뤄야 할 때
4. 애플리케이션 코드를 바꿔야 해결되는 문제를 발견했을 때

## 다루지 않는 것

- 애플리케이션 코드는 백엔드 세션이나 디자이너 세션에서 다룬다.
- 측정, 부하 테스트 실행, 성능 분석은 관측 세션에서 다룬다.
