# 백엔드

이 세션의 주제는 백엔드 설계와 구현이다. 백엔드는 사용자의 전문 영역이다. 사용자가 설계와 구현을 주도하고, 이 세션은 그 과정을 돕거나 지정받은 범위를 구현한다.

공통 규칙과 코드 작업 규칙은 CLAUDE.md를 따른다. 아래는 이 세션에만 해당하는 내용이다.

## 입력

- `InternalDocs/SPEC.md`와 작업 대상 spec을 읽는다.
- 기존 기능을 고치는 작업이면, 그 기능과 관련된 `InternalDocs/TroubleShooting/`와 `InternalDocs/Adr/` 문서도 읽는다. 과거에 왜 그렇게 결정했는지 알고 고친다.
- 관련 없는 문서는 읽지 않는다.

## spec 작성

API 명세, 구현 방법, 멈출 조건, 테스트 방법은 사용자가 주도해서 쓴다. 다음 순서를 따른다.

1. 사용자가 작성할 때, 질문에 답하고 고려할 점을 짚어 돕는다.
2. 사용자의 초안이 나오면, 부족한 부분을 짚고 보완안을 제안한다.
3. 사용자가 요청하면 최종본을 정리해 작성한다.
4. 사용자가 최종본을 검수하고 확정한다. 확정 전까지는 완성된 것으로 취급하지 않는다.

## 아키텍처 문제 보고

구현 중 spec에서 정한 아키텍처로는 해결할 수 없는 문제를 발견하면, 구현을 멈추고 다음을 이 세션 안에서 정리해 보고한다. 사용자는 이 보고를 들고 PM 세션에서 해결 방향을 정한다.

- 상황: 어떤 작업 중에 발견했는가
- 문제: 무엇이 왜 안 되는가
- 근거: 확인한 코드, 로그, 측정값

## 멈출 조건 (백엔드)

공통 멈출 조건에 더해, 다음 상황에서도 멈추고 사용자에게 보고한다.

1. spec에서 정한 아키텍처로 해결할 수 없는 문제를 발견했을 때
2. API 명세를 바꿔야 할 때 (프론트엔드에 영향을 준다)

## 다루지 않는 것

- 프론트엔드 코드는 디자이너 세션에서 다룬다.
- 성능 측정과 분석, 부하 테스트, 성능 개선은 관측 세션에서 다룬다.
